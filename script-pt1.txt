PART 2 — Vulnerability Demonstrations
Vulnerability 1 — IDOR on Orders

[Showing screen: Burp Suite — Proxy tab, intercept off]

"Moving into the penetration testing phase. I'm using Burp Suite Community Edition — the industry standard for web application security testing. The browser is proxied through Burp so I can intercept and modify every request."

[Showing screen: Browser — logged in as User A, own order page /orders/3]

"I'm logged in as User A. I've just purchased a ticket and I'm viewing my own order at /orders/3. This is legitimate access — my order, my data."

[Showing screen: Burp Suite — turn Intercept ON]

"Now I'm going to turn on Burp's intercept and manually navigate to the orders endpoint."

[Showing screen: Browser — type /orders/2 in URL bar]

"I'm changing the order ID from 3 to 2 — which belongs to User B. This is a completely different user's private order."

[Showing screen: Burp Suite — intercepted GET /orders/2 request]

"Burp has captured the request. I can see it's a GET request to /orders/2. No ownership verification is happening server-side. Let me forward it."

[Showing screen: Browser — User B's order data displayed]

"And there it is. I'm logged in as User A and I'm viewing User B's complete order — their event, their purchase amount, their ticket IDs. This is a critical IDOR vulnerability. The application trusted the ID in the URL without checking whether the logged-in user actually owns that order."

[Take screenshot]

[Showing screen: Admin logs]

"And notice in the admin activity log — this access attempt has been recorded. The system logged it but couldn't prevent it. That's the problem we'll fix."

Vulnerability 4 — XSS Attempt

[Showing screen: Browser — logged in as organizer, Create Event page]

"Now testing for Cross-Site Scripting. I'm going to attempt to inject a script tag into the event description field."

[Type in description field:]

<script>alert('XSS')</script>

[Submit the form]

[Showing screen: Event detail page]

"Navigating to the event page to see if the script executes."

If alert fires:

"The script executed — confirmed stored XSS vulnerability. Any user viewing this event page would have this script run in their browser. An attacker could use this to steal session cookies, redirect users, or perform actions on their behalf."

If alert does not fire:

"The script did not execute — React's JSX rendering automatically escapes HTML entities, converting the script tag to plain text. This is a framework-level security control working correctly. However this should be noted — if any part of the application used dangerouslySetInnerHTML, this would be exploitable. We verified no such usage exists in our codebase."

[Take screenshot either way]
Vulnerability 5 — Business Logic Flaw (Race Condition)

[Showing screen: Limited Event page — 1 ticket available]

"The fifth and final vulnerability is a business logic flaw — specifically a race condition in the ticket purchasing flow. This is more sophisticated than the previous vulnerabilities and demonstrates a class of bug that automated scanners typically miss entirely."

[Showing screen: OrderController.php — the vulnerable code]

"Looking at the source code — the application checks ticket availability here, then creates the order and decrements the counter here. Between these two operations there is a window — however small — where two simultaneous requests can both pass the availability check before either one decrements the counter."
php

// Check happens here — both requests pass this
if ($event->availableTickets() < $request->quantity) {
    return back()->withErrors([...]);
}

// Window of vulnerability — race condition lives here

// Decrement happens here — both requests reach this
$event->increment('tickets_sold', $quantity);

[Showing screen: Terminal]

"I'm going to simulate two simultaneous purchase requests using curl — firing them at exactly the same time."
bash

curl -X POST http://127.0.0.1:8000/orders/checkout \
  -H "Content-Type: application/json" \
  -b "laravel_session=YOUR_SESSION" \
  -d '{"event_id":2,"quantity":1}' &

curl -X POST http://127.0.0.1:8000/orders/checkout \
  -H "Content-Type: application/json" \
  -b "laravel_session=YOUR_SESSION" \
  -d '{"event_id":2,"quantity":1}' &

wait

[Showing screen: Database result in tinker]
bash

php artisan tinker

php

$event = App\Models\Event::find(2);
echo "Total tickets: " . $event->total_tickets;
echo "Tickets sold: " . $event->tickets_sold;
echo "Tickets generated: " . App\Models\Ticket::where('event_id', 2)->count();

"Total tickets: 1. Tickets sold: 2. Two tickets generated for a one-ticket event. The race condition allowed both requests to succeed — the event is now oversold. This is a direct financial and operational impact."
